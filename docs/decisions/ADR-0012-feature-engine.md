# ADR-0012: One order-flow feature engine for live and replay (Phase 3)

- Status: Proposed (2026-10-25), for operator review with the Phase 3 PR
- Context: Phase 3's exit gate is identical features live and in replay on the same ticks. Nautilus `TradeTick` has no venue or sale conditions, and the features need both (ISO sweeps, off-exchange share, which prints get an aggressor side). Trades and quotes come on separate live channels and can arrive slightly out of order.
- Decisions:
  1. **Pure-Python engine, no wall clock.** `flowforge.features.engine.FeatureEngine` takes trades and quotes and emits plain-dict records. Its output depends only on the events, so parity can be tested byte for byte.
  2. **Sequencer.** Every event goes through a buffer that releases it once the newest exchange timestamp is 50 ms past it, ordered by (timestamp, trade before quote at the same ns, exchange + id / arrival). Live latency cost is that window. Events older than what was already released are dropped and counted (`late_events_total`); they are the only way live can differ from replay.
  3. **Full trades on the bus.** The Alpaca client also publishes `TapeTrade` custom data (venue, conditions, tape) to actors that subscribe to it. In replay, the same fields come from the raw trade files joined on trade id (ADR-0010).
  4. **Classification**: quote rule at the NBBO in force (Lee–Ready without the 5 s delay), tick test at the midpoint or when the NBBO is locked, crossed or missing; off-market and auction prints get no side. Condition classes follow the UTP Sale Condition Matrix (docs/research/11).
  5. **Book definitions** (Trader Dale): Bid × Ask footprint, Delta = Ask − Bid, CumDelta resets daily, diagonal 300% imbalances stacked 3+, unfinished business (high with Bid > 0, low with Ask > 0), absorption = heavy Bid **and** Ask at one row while the range stalls, big limit order = one very heavy cell, trades filter = big single prints. Thresholds are hypotheses in `FeatureConfig`, to be tuned and tested in Phase 5.
  6. Footprint row height is about 1 bp of the day's first price, rounded to $0.01/0.02/0.05/0.10/...; levels come from 5- and 30-minute bars.
  7. **Three-path parity check** (`python -m flowforge.features.parity`): catalog → engine; catalog → Nautilus BacktestEngine → actor; ticks re-sent as Alpaca stream messages → real client and LiveNode → actor. Only the network is faked.
- Consequences: Strategies (Phase 5) read features from this one engine in backtest and live. Bars close when the first event after their end arrives (or at session flush), not on a timer, so a quiet symbol's bar can close late; Phase 4 may add a clock-driven close if strategies need it. Depth features stay out until IBKR TotalView is wired (Nasdaq-book-only, never faked). Live outages are not yet marked as gaps in live bars (replay marks Phase 2 gaps); that belongs with Phase 4's feed-drop tests.
